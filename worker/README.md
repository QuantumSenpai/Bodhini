# Phase 4 AI proxy foundation

This Cloudflare Worker is a local foundation. Its deployed entrypoint has no provider adapter and returns `503 provider_unavailable`. No live model call, mobile wiring, credential, or deployment is included.

Run `npm run test:worker` for the fast Node Web API suite and `npm run test:worker:runtime` for local Cloudflare runtime verification. `npm run check` runs both. The runtime command bundles the configured production entrypoint and a separate `test/runtime-entry.ts` fake-provider entrypoint, then dispatches requests through Miniflare's local `workerd`. It needs no account or deployment. The locked tools are Miniflare 4.20260730.0, workerd 1.20260730.1, and esbuild 0.28.2; the runtime suite was verified with Node 26.9.0. `wrangler.toml` pins compatibility date 2026-08-06, the newest date accepted by this workerd binary, with `enable_request_signal` explicitly enabled. The test reads that date and flag from the same file. Cloudflare documents [Miniflare's local workerd runtime](https://developers.cloudflare.com/workers/testing/miniflare/), [programmatic dispatch](https://developers.cloudflare.com/workers/testing/miniflare/core/fetch/), and the [request-signal flag](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#enable-requestsignal-for-incoming-requests).

The local runtime suite verifies the disabled production entrypoint's 503 and route errors; fake-provider mappings, empty and manual actions; strict validation and stable IDs; the 16,384-byte incoming and 8,192-byte provider-output limits with multibyte text, missing and false-low length headers, and oversized chunks; separate two- and five-second deadlines; observed timer and stream cleanup; and Phase 3C client fallback. A synthetic request constructed inside workerd tests misleading `Content-Length`, since a local HTTP dispatcher may normalize transport framing. A manually aborted signal inside workerd reaches the 499 path. That does not establish how a deployed Worker observes a real disconnected HTTP client, which still needs deployed-runtime verification. The test-only entrypoint is outside the configured `src/index.ts` main and cannot be selected by a production request header or setting.

`POST /v1/form-labels` accepts exactly `{ "language": "en", "labels": [{ "id": "f0", "label": "Applicant Name" }] }`. Language is `en`, `hi`, or `bn`; IDs are unique positional `f0` through `f39`, including gaps after filtering. The request has at most 40 labels, 120 code points per transmitted label, and 16,384 actual UTF-8 body bytes. Incoming body reading has a separate two-second deadline starting before consumption. A stalled body returns `408 request_timeout`, caller cancellation returns `499 cancelled`, and an oversized body returns `413 request_too_large`. Unread bodies are cancelled on early rejection without waiting for cancellation to settle. Unexpected properties, methods, paths, and media types are rejected. Successful output is exactly `{ "suggestions": [{ "id": "f0", "action": "map", "key": "FULL_NAME" }] }`, or a validated `manual` action with type `SIGNATURE` or `DECLARATION`. An empty array is valid. Errors use short fixed codes and no reflected input. All responses have `Cache-Control: no-store`.

The server independently repeats the client sanitizer and preserves original opaque IDs when labels are dropped or masked. It normalizes NFKC and JavaScript whitespace, drops `@` labels, masks the documented date, PAN, long decimal digit, and grouped identifier patterns, and rejects a third affected label. This pattern filter cannot remove arbitrary names, addresses, or other personal text.

The injected provider receives a fixed server-owned instruction, sanitized labels, an abort signal, and an 8,192-byte output budget. After input validation, the handler gives it five seconds, reads its `Response` body incrementally, cancels an oversized stream, validates the exact Phase 3C response schema, and checks the final serialized output against 8,192 UTF-8 bytes. The client allows eight seconds; the two-second incoming deadline and five-second provider deadline leave about one second for network and processing overhead in the worst allowed case. A future fetch-based adapter must return the raw streaming response, not call `text()` or `arrayBuffer()` first. It must take the provider endpoint, model settings, and credential only from trusted Worker configuration, and use a Worker secret binding for the credential. There are no required secret bindings in this disabled foundation.

Before public deployment, choose and implement access control and a shared rate limit. No local or global rate limiter exists yet. CORS is deliberately absent because the current Android client uses native fetch; CORS is not authentication. Review provider data-use terms, configure the secret and provider adapter, verify the Cloudflare runtime and cancellation behavior, and add deployment configuration and operational limits before enabling traffic. The mobile flow also still needs unknown OCR label intake, default-off localized consent, AI provenance, confirmation, and current-scope checks. Keep synthetic values in all diagnostics and tests.
