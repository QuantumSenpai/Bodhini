# Phase 4 AI proxy foundation

This Cloudflare Worker is a local foundation. Its deployed entrypoint has no provider adapter and returns `503 provider_unavailable`. No live model call, mobile wiring, credential, or deployment is included.

Run `npm run test:worker` from the repository root. `npm run check` also runs the Worker suite. Tests call the real `handleProxy` with Web `Request` and `Response` objects and fake providers. The Worker configuration is in `wrangler.toml`; no Wrangler dependency or Cloudflare account is needed for these local checks.

`POST /v1/form-labels` accepts exactly `{ "language": "en", "labels": [{ "id": "f0", "label": "Applicant Name" }] }`. Language is `en`, `hi`, or `bn`; IDs are unique positional `f0` through `f39`, including gaps after filtering. The request has at most 40 labels, 120 code points per transmitted label, and 16,384 actual UTF-8 body bytes. Unexpected properties, methods, paths, and media types are rejected. Successful output is exactly `{ "suggestions": [{ "id": "f0", "action": "map", "key": "FULL_NAME" }] }`, or a validated `manual` action with type `SIGNATURE` or `DECLARATION`. An empty array is valid. Errors use short fixed codes and no reflected input. All responses have `Cache-Control: no-store`.

The server independently repeats the client sanitizer and preserves original opaque IDs when labels are dropped or masked. It normalizes NFKC and JavaScript whitespace, drops `@` labels, masks the documented date, PAN, long decimal digit, and grouped identifier patterns, and rejects a third affected label. This pattern filter cannot remove arbitrary names, addresses, or other personal text.

The injected provider receives a fixed server-owned instruction, sanitized labels, an abort signal, and an 8,192-byte output budget. The handler gives it five seconds, reads its `Response` body incrementally, cancels an oversized stream, validates the exact Phase 3C response schema, and checks the final serialized output against 8,192 UTF-8 bytes. The client allows eight seconds, leaving roughly three seconds for network overhead. A future fetch-based adapter must return the raw streaming response, not call `text()` or `arrayBuffer()` first. It must take the provider endpoint, model settings, and credential only from trusted Worker configuration, and use a Worker secret binding for the credential. There are no required secret bindings in this disabled foundation.

Before public deployment, choose and implement access control and a shared rate limit. No local or global rate limiter exists yet. CORS is deliberately absent because the current Android client uses native fetch; CORS is not authentication. Review provider data-use terms, configure the secret and provider adapter, verify the Cloudflare runtime and cancellation behavior, and add deployment configuration and operational limits before enabling traffic. The mobile flow also still needs unknown OCR label intake, default-off localized consent, AI provenance, confirmation, and current-scope checks. Keep synthetic values in all diagnostics and tests.
